# Code Implementation Plan

## Overview

Build a Quarto static website that reproduces the visual design of the
al-folio Jekyll theme. The site uses a left sidebar layout (profile photo,
name, affiliation, social icon links, and page navigation) with the main
content area on the right. Five pages make up the site: About (homepage),
Publications (rendered from BibTeX seeded from Google Scholar), Projects
(four research projects), CV (English HTML page plus downloadable PDF), and
Teaching (full portfolio with links). The site deploys to GitHub Pages
(`rekkasa.github.io`) via a GitHub Actions workflow. A companion R script
(`R/fetch_publications.R`) scrapes the author's Google Scholar profile
once to produce `publications.bib`.

**Note**: No `ARCHITECTURE.md` was available at the time this plan was
written — the architecture described here is derived from `OBJECTIVES.md`
and the conversation context alone. (Actually, ARCHITECTURE.md does exist
and is consistent.)

## Language and Stack

- **Language**: R 4.6+, Quarto Markdown (`.qmd`), HTML, SCSS/CSS
- **Key R packages**: `scholar`, `rvest`, `RefManageR`, `stringr`, `dplyr`,
  `purrr`, `tibble`, `readr`, `htmltools` (for programmatic HTML in
  publications page)
- **Key non-R dependencies**: Quarto CLI 1.6+, Bootstrap 5 (bundled with
  Quarto), Academicons CSS (for Google Scholar icon), Font Awesome
  (bundled with Quarto)
- **Style conventions** (from `STYLE_GUIDE.md`):
  - Native pipe `|>` — never `%>%`. Trailing pipe at end of line.
  - No `library()` or `require()` — always `package::function()`.
  - Named arguments for every function call, each on its own line.
  - `snake_case` for all user-defined names.
  - Double quotes for strings, `TRUE`/`FALSE` spelled out.
  - 80-character line limit.
  - `<-` for assignment, `=` only in function argument lists.

### `_quarto.yml` — New

**Responsibility**: Top-level Quarto project configuration and site metadata.
Defines the Bootstrap theme, disables default navbar/sidebar in favor of a
custom sidebar injected via `include-before-body`, and sets Academicons for
the Google Scholar icon.

**Key configuration**:

- `project.type`: `"website"`
- `project.output-dir`: `"_site"`
- `website.title`: `"Alexandros Rekkas"`
- `website.favicon`: pointing to a favicon file or empty
- `website.navbar`: `false` (disabled — sidebar handles all navigation)
- `website.page-navigation`: `false`
- `website.page-footer`: copyright line, e.g. `"© 2026 Alexandros Rekkas"`
- `format.html.theme`: `[cosmo, styles.scss]` — use `cosmo` as Bootstrap base,
  override with custom `styles.scss`
- `format.html.toc`: `false`
- `format.html.include-before-body`: `"_includes/sidebar.html"`
- `format.html.include-in-header`: a raw HTML `<link>` tag for Academicons CSS:
  ```
  https://cdn.jsdelivr.net/gh/jpswalsh/academicons@1/css/academicons.min.css
  ```
- No `execute` freeze needed for a static site, but set
  `execute.freeze: auto` to avoid re-executing unless inputs change.

**Website navbar listing** (used for Quarto's internal page registry, not
visually rendered since navbar is disabled):

```yaml
website:
  navbar:
    left:
      - text: "About"
        href: index.qmd
      - text: "Publications"
        href: publications.qmd
      - text: "Projects"
        href: projects.qmd
      - text: "CV"
        href: cv.qmd
      - text: "Teaching"
        href: teaching.qmd
```

Wait — this would render a top navbar. Since navbar is `false`, Quarto
still needs to know about the pages for site generation. Instead, list
pages under `website` with `sidebar` set to a minimal structure used
only for page discovery. In Quarto, listing all pages in
`website.sidebar.contents` (or `website.contents` in newer versions)
ensures they are rendered. Use `website.sidebar.style: "docked"` but
with CSS hiding the default sidebar and replacing it with the custom
one. **Decision**: list pages in `website` config for site awareness but
suppress rendering the default sidebar via CSS. The custom sidebar
HTML replicates the nav links.

**Pseudocode for `_quarto.yml` structure**:
```
1. project block:
     type: website
     output-dir: _site
     execute:
       freeze: auto
2. website block:
     title: "Alexandros Rekkas"
     favicon: <none for now, can be added later>
     navbar: false
     page-navigation: false
     page-footer:
       center: "© 2026 Alexandros Rekkas"

       contents:
         - text: "About"
           href: index.qmd

         - text: "Projects"
           href: projects.qmd
         - text: "CV"
           href: cv.qmd

       theme:
         light: [cosmo, styles.scss]
```

### `styles.scss` — New

**Responsibility**: Custom SCSS that overrides Bootstrap 5 variables and adds
al-folio sidebar layout, typography, card styles, and responsive breakpoints.

**Key design elements**:

- **Body flex layout**: turn `<body>` into a flex container so the sidebar
  sits on the left (fixed width) and Quarto's content fills the right.
- **Sidebar styling**:
  - Fixed width of ~280px, full viewport height, `position: sticky; top: 0`
  - Dark background (al-folio uses `$grey-color-dark` or similar — target
    `#2c3e50` or `#34495e`), white text
  - Profile photo: circular crop, centered, max-width ~180px
  - Name and affiliation: centered text below photo
  - Social icon links: horizontal row, centered, Font Awesome / Academicons
    icons, hover color change
  - Nav links: vertical list, styled as text links with hover underline
  - Scrollable internally if content exceeds height
- **Main content area**:
  - Flex: 1, padding 2–3rem, max-width ~900px or full width
  - Use Quarto's `#quarto-content` or `.content` selector
- **Publication cards**:
  - Bootstrap card-style (`border`, `border-radius`, shadow on hover)
  - Entry layout: title (bold), authors (smaller), venue/journal (italic),
    year, links row (badges/pills)
  - Same as al-folio's `.publications` styles
- **Project cards**:
  - Grid of Bootstrap cards, 1–2 per row depending on viewport
  - Each card: project name, funding, timeline, description
- **CV page**: clean typography, section headings with left border accent,
  list-based layout
- **Responsive**: on screens < 768px, sidebar collapses into a top bar or
  becomes toggleable. Main content goes full width.

### `R/fetch_publications.R` — New

**Responsibility**: One-time script to scrape the author's Google Scholar
profile and produce a `publications.bib` file. Uses the `scholar` package
as primary method, with `rvest`-based manual scraping as fallback if
Scholar blocks automated access.

**Exported functions**:

#### `fetch_publications(scholar_id, output, force)`

- **Purpose**: Scrape Google Scholar profile for all publications, convert
  to BibTeX, and write to a `.bib` file.
- **Args**:
  - `scholar_id` (`character`): Google Scholar user ID. Default
    `"2VGBdDwAAAAJ"`.
  - `output` (`character`): Path to write BibTeX output. Default
    `"publications.bib"`.
  - `force` (`logical`): If `TRUE`, overwrite existing output file.
    Default `FALSE`.
- **Returns**: `character` — invisibly returns the path to the written file,
  or throws an error.
- **Errors**:
  - If the output file exists and `force = FALSE`, abort with:
    `rlang::abort("Output file already exists. Set force = TRUE to overwrite.")`
  - If both `scholar` and `rvest` approaches fail, abort with the last
    captured error message.
- **Pseudocode**:
  ```
  1. Validate: if output file exists AND force is FALSE, abort
  2. Try primary approach: scholar_get_bibtex(scholar_id):
     a. Call scholar::get_publications(id = scholar_id)
        to retrieve data frame of publications
     b. For each publication, call scholar::get_bibtex() to get BibTeX
     c. Combine all BibTeX entries into a single character vector
     d. Attempt to title-case-protect entries by wrapping
        uppercase words in {} braces
     e. If scholar succeeds, write to output and return path
  3. If scholar fails (error or empty result):
     a. Try fallback: fetch_publications_rvest(scholar_id):
        1. Build URL: "https://scholar.google.com/citations?user={scholar_id}&hl=en&sortby=pubdate&pagesize=100"
        2. Fetch HTML with rvest::read_html(url = url)
        3. Check for CAPTCHA indicators (page title, specific strings)
           → if detected, abort with "Google Scholar returned a CAPTCHA.
           Manual entry required. Please export your publications from
           https://scholar.google.com and save as publications.bib"
        4. Extract publication rows using CSS selector:
           rvest::html_elements(x = page, css = "tr.gsc_a_tr")
        5. For each row:
           a. Extract title, authors, venue, year, and citation link
           b. Follow citation link to get full BibTeX entry via
              rvest::html_element(css = "div.gsc_vcd_value")
           c. Parse into BibTeX format
        6. Combine entries and write to output
     b. If rvest also fails, abort with collected error info
  4. Return invisible(output)
  ```

**Internal helpers** (not exported):

#### `scholar_get_bibtex(scholar_id)`

- **Purpose**: Use `scholar` package to retrieve publications and their
  BibTeX entries.
- **Args**: `scholar_id` (`character`): Google Scholar ID.
- **Returns**: `character` — combined BibTeX string.
- **Pseudocode**:
  ```
  1. pubs <- scholar::get_publications(id = scholar_id)
  2. If nrow(pubs) == 0, throw error "No publications found"
  3. bib_vec <- purrr::map_chr(
       .x = pubs$pubid,
       .f = \(pid) scholar::get_bibtex(id = scholar_id, pubid = pid)
     )
  4. Concatenate with stringr::str_c()
  5. Return combined BibTeX string
  ```

#### `fetch_publications_rvest(scholar_id)`

- **Purpose**: Fallback manual scraper using `rvest`.
- **Args**: `scholar_id` (`character`): Google Scholar ID.
- **Returns**: `character` — combined BibTeX string.
- **Pseudocode**:
  ```
  1. Build profile URL with scholar_id
  2. page <- rvest::read_html(x = url)
  3. Check for CAPTCHA:
       title <- rvest::html_text(rvest::html_element(page, "title"))
       If stringr::str_detect(title, "robot|CAPTCHA|captcha"),
         abort("Google Scholar blocked the request")
  4. rows <- rvest::html_elements(x = page, css = "tr.gsc_a_tr")
  5. If length(rows) == 0, abort("No publication rows found")
  6. entries <- purrr::map(
       .x = rows,
       .f = parse_publication_row
     )
  7. Combine entries with "\n\n" separator
  8. Return combined BibTeX
  ```

#### `parse_publication_row(row)`

- **Purpose**: Parse a single publication row HTML node into a BibTeX string.
- **Args**:
  - `row` (`xml_node`): An `<tr>` element from Google Scholar's
    publications table.
- **Returns**: `character` — BibTeX entry string.
- **Pseudocode**:
  ```
  1. Extract title from the row's <a class="gsc_a_at"> text
     (Remove trailing period if present)
  2. Extract authors from the <div class="gs_gray"> first child text
  3. Extract venue from the <div class="gs_gray"> second child text
  4. Extract year from <span class="gsc_a_h gsc_a_hc gs_ibl"> text
  5. Generate a citation key:
     first_author_lastname + last_two_digits_of_year + first_title_word
     (lowercased, alphanumeric only)
  6. Format as BibTeX @article{...} entry with available fields
  7. Return BibTeX string
  ```

**New packages needed** (add to `renv.lock`): `scholar`, `rvest`, `xml2`,
`stringr`, `purrr`, `rlang`, `dplyr`.

### `publications.qmd` — New

**Responsibility**: Renders publications from `publications.bib` as
al-folio-style cards (title, authors, venue, year, links). Uses an R code
chunk with `#| output: asis` to emit raw HTML.

**Front matter**:
```yaml
---
title: "Publications"
---
```

**Core logic** (R chunk):
```
1. Read publications.bib using RefManageR::ReadBib(file = "publications.bib")
2. Extract fields into a tibble:
     cols: key, title, author, journal, year, doi, url, abstract
3. Sort by year descending
4. Group by year
5. For each year group:
   a. Emit <h2 class="pub-year">{year}</h2>
   b. For each publication in the group:
      - Build a <div class="pub-card"> containing:
        <div class="pub-title">
          {if doi/url available, wrap in <a href="...">}
        </div>
        <div class="pub-authors">{formatted author list}</div>
        <div class="pub-venue">
          <em>{journal}</em>, {year}
        </div>
        <div class="pub-links">
          {if doi: <a class="badge" href="...">DOI</a>}
          {if url: <a class="badge" href="...">URL</a>}
          {if abstract: <a class="badge" data-bs-toggle="collapse"
                           href="#abstract-{key}">Abstract</a>}
        </div>
        {if abstract:
          <div class="collapse" id="abstract-{key}">
            <div class="pub-abstract">{abstract}</div>
          </div>}
      - Emit closing </div>
```

**Author formatting**: Convert BibTeX author strings (e.g., "Rekkas,
Alexandros and Rijnbeek, Peter R.") into "A. Rekkas, P. R. Rijnbeek"
format. Use `RefManageR::ReadBib()` author list and format with
`format(entry$author, include = c("given", "family"))` or manual
stringr-based parsing.

**Pseudocode for the R chunk**:
```
1. bib <- RefManageR::ReadBib(file = "publications.bib", check = FALSE)
2. n <- length(bib)
3. If n == 0, cat("<p>No publications found.</p>") and return
4. pub_tbl <- tibble::tibble(
     key = names(bib),
     title = purrr::map_chr(bib, ~ .x$title %||% ""),
     author = purrr::map_chr(bib, ~ paste(.x$author, collapse = ", ") %||% ""),
     journal = purrr::map_chr(bib, ~ .x$journal %||% ""),
     year = purrr::map_chr(bib, ~ as.character(.x$year) %||% ""),
     doi = purrr::map_chr(bib, ~ .x$doi %||% ""),
     url = purrr::map_chr(bib, ~ .x$url %||% ""),
     abstract = purrr::map_chr(bib, ~ .x$abstract %||% "")
   )
5. pub_tbl <- dplyr::arrange(pub_tbl, dplyr::desc(year))
6. years <- unique(pub_tbl$year)
7. For each year in years:
   a. cat('<h2 class="pub-year">', year, '</h2>\n', sep = "")
   b. year_pubs <- dplyr::filter(pub_tbl, year == !!year)
   c. For each row in year_pubs:
      - Build and cat() the pub-card div as described above
```

**New packages needed** (add to `renv.lock`): `RefManageR`, `htmltools`,
`tibble`, `dplyr`, `purrr`, `stringr`. `htmltools` provides
`htmltools::htmlEscape()` for safe HTML attribute output.

### `.github/workflows/publish.yml` — New

**Responsibility**: GitHub Actions workflow that builds the Quarto site and
deploys to the `gh-pages` branch.

**Key steps**:

1. Checkout repository with `fetch-depth: 0`
2. Set up Quarto CLI (use `quarto-dev/quarto-actions/setup@v2`)
3. Set up R with `renv` restoration
4. Render the site: `quarto render`
5. Deploy `_site/` to `gh-pages` branch using
   `peaceiris/actions-gh-pages@v3`

**Pseudocode for workflow YAML**:
```
name: Publish website
on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      1. actions/checkout@v4
      2. quarto-dev/quarto-actions/setup@v2
      3. r-lib/actions/setup-r@v2 (with renv cache)
      4. Restore renv packages: renv::restore()
      5. Run: quarto render
      6. peaceiris/actions-gh-pages@v3:
           github_token: ${{ secrets.GITHUB_TOKEN }}
           publish_dir: _site
           publish_branch: gh-pages
```

## Data Flow

```
R/fetch_publications.R
    │  (one-time scrape of Google Scholar)
    ▼
publications.bib ────────────────────────────────────┐
    │                                                 │
    ▼                                                 ▼
publications.qmd (R chunk: RefManageR::ReadBib)     _quarto.yml
    │ (generates HTML cards)                          │ (configures site,
    ▼                                                 │  sidebar, theme)
index.qmd ──────────────┐                            │
projects.qmd ───────────┤                            │
cv.qmd ─────────────────┤                            │
teaching.qmd ───────────┤                            │
    │                    │                            │
    ▼                    ▼                            ▼
  All .qmd files ──► quarto render ──► _site/ (static HTML + CSS + JS)
                                          │
                                          ▼
                                  GitHub Actions
                                  (publish.yml)
                                          │
                                          ▼
                                  gh-pages branch
                                          │
                                          ▼
                                  rekkasa.github.io
```

The render flow:
1. `_quarto.yml` declares the project and picks up all `.qmd` files
2. `styles.scss` overrides Bootstrap to implement al-folio sidebar layout
3. `_includes/sidebar.html` is injected into every page
4. `publications.qmd` reads `publications.bib` at render time via an R chunk
5. All pages produce HTML in `_site/`
6. `cv.pdf` is a static file copied to `_site/` (or linked from `cv.qmd`
   with a relative path)
7. GitHub Actions pushes `_site/` to `gh-pages`
